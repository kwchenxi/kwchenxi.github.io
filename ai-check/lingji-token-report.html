金蝶灵基 — Design Token 扫描报告

扫描范围：全应用（app.asar 解包） 扫描时间：2026-08-10 应用版本：0.1.2（Electron）

这是什么？

设计系统都会定义一套Token 变量：比如主色叫 --lg-primary-600，值是 #495DFF。开发写代码时应该用变量而不是直接写色值——这样哪天品牌色换了，改一个变量全局生效，不用挨个文件去找。

但实际项目中，难免有人图方便直接写 background: #495DFF。以前只能靠 code review 人肉找，现在可以让 AI 自动扫描。

怎么扫的？

1

解包应用

灵基是 Electron 应用，前端代码打包在 app.asar 里（就在 /Applications/金蝶灵基.app/Contents/Resources/ 下面）。用 Electron 官方工具解包，得到所有 CSS 和 JS 文件。

2

正则扫描

用正则匹配所有 CSS/JS 文件，统计两类东西：
• Token 用法：var(--lg-primary-600)、var(--lg-r-x-medium) 等
• 硬编码：直接写的 #495DFF、border-radius: 8px、font-size: 14px

3

分类过滤

不是所有硬编码都是问题。工具会自动分类：
• Token 定义（--lg-primary-600: #495DFF）→ 正常
• CSS fallback（var(--lg-primary-600, #495dff)）→ 正常
• Tailwind 编译产物 → 低风险
• SVG 图标填色 → 单独分类
• 真正的硬编码 → 需要关注

主要发现

做得好的：灵基自己的组件代码 Token 使用率很高，主色 #495DFF 基本都走了 var(--lg-primary-600)。Shadow、Transition 等 Token 也都有使用。

需要关注的：

  • 登录页（login.css）的按钮、链接色直接写了 #495DFF
  • 小程序/WebView 窗口（miniapp.css、imageViewer.css）大量使用 iOS 蓝 #007AFF 而非灵基主色
  • JS 内联色值：Toast 提示、Checkbox 图标、加载 Spinner 在 JS 中直接写了色值
  • 圆角和字号虽然值匹配 Token，但直接写 px 而非用变量
注意：这个工具只检查"有没有用变量"，不判断"该不该用这个色"——比如某个场景就该用 #007AFF 而不是主色，这需要设计师来判断。
