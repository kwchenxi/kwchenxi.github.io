严重问题（优先修复）

严重

#1 小窗口下筛选栏被截断/溢出

▼
位置顶部筛选栏（日期、时间、区域、标签、搜索）
表现窗口缩小时，日期和时间控件仍占据大量宽度，右侧"全部区域/全部标签/搜索会议室"被挤出可视范围，且无水平滚动条提示用户右侧还有内容。
影响用户在小窗口下无法完整使用筛选条件，搜索入口不可见或不可用。
建议：窄宽下筛选栏自动换行；或将区域、标签、搜索收纳为"筛选"抽屉；或支持横向滚动并显示明确滚动提示。
严重

#2 小窗口下卡片仍强制3列，内容被严重压缩

▼
位置会议室卡片列表区域
表现窗口变窄后仍保持3列布局，每张卡片宽度被严重压缩。容量信息出现"可容/纳4人""可容/纳14/人"等异常换行，会议室名称被截断为"云卷亭（B8..."。
影响卡片可读性明显下降，用户无法确认完整会议室名称和容量信息。
建议：增加响应式断点 — 宽屏3列 → 中屏2列 → 窄屏1列。容量信息设置 white-space: nowrap，作为不可拆分的 inline-flex 元素。
严重

#3 预订界面打开为独立大窗口，不符合 Dialog 弹窗规范

▼
位置点击"立即预订"后的新建会议界面
表现打开的是独立窗口（约1080×700px），而 Lingee UI 规范要求弹窗宽度为小460px / 中640px / 大720px。用户上下文被打断，与轻量预订体验不一致。
影响用户从会议室列表跳转到全新窗口，操作沉浸感被打断，与"立即预订"的轻量语义不符。
建议：改为居中 Modal 弹窗（推荐720px大尺寸）；若业务确实需要完整新建会议窗口，应在设计规范中明确例外说明。

中等问题

中等

#4 左侧导航在小窗口下未折叠，占用过多宽度

▼
位置左侧 Lingee 导航栏
表现左侧导航始终完整显示，在小窗口下仍占据较大宽度，导致右侧内容区严重不足。
建议：窄屏时自动折叠为图标栏，或提供收起按钮并默认在小宽度下收起。
中等

#5 会议室名称/地点信息被截断，可读性不足

▼
位置卡片标题行和地点行
表现会议室名称显示为"云卷亭（B8..."，楼层显示为"B栋..."。虽有省略号，但可读信息不足，用户无法确认完整名称。
建议：增加 title tooltip；或允许卡片名称两行显示；窄屏时优先保证地点信息完整。
中等

#6 超宽状态下卡片过度拉伸，内部空白过多

▼
位置全屏/最大化状态下的会议室卡片
表现卡片横向宽度很大，左侧信息与右侧"立即预订"按钮距离很远，中间空白较多，信息密度偏低。
建议：设置卡片最大宽度；超宽时增加列数至4列；或将列表容器设置 max-width 并居中。
中等

#7 日期输入框可选中但不可编辑，交互反馈不一致

▼
位置顶部筛选栏，开始/结束日期输入框
表现日期文本可以被选中，视觉上像可编辑输入框，但键盘输入日期不生效。用户尝试修改时会困惑。
建议：禁用文本选中（只读态），或支持直接键盘编辑。对齐 Input 组件规范。
中等

#8 "立即预订"按钮高度疑似偏小

▼
位置每张会议室卡片右侧
表现按钮视觉高度约22-24px，未明显达到 Lingee UI 规范 md 规格的28px高度。点击热区和视觉层级偏弱。
建议：确认实际 CSS height/line-height/padding，确保符合设计规范 md（28px）按钮尺寸。
中等

#9 新建会议右侧时间轴/时区信息理解成本高

▼
位置新建会议窗口右侧日程视图
表现左侧表单显示19:30-20:30，右侧时间轴出现01:45/19:45等红色标记，并有GMT-10/GMT+8两列，与用户选择的会议时间不直观对应。
建议：突出当前会议时间块，弱化非当前时区信息；或补充明确时区说明。
中等

#10 容量信息异常换行（"可容/纳4人"）

▼
位置多张卡片的容量行
表现"可容纳4人"被拆为"可容/纳4人"，"可容纳14人"被拆为"可容/纳14/人"，不自然断行，阅读体验差。
建议：设置 white-space: nowrap，图标+文本整体作为 inline-flex 不可拆分元素。

轻微问题

轻微

#11 搜索框焦点状态不够明显

▼
表现输入后搜索框没有非常明显的主色描边，焦点感较弱，键盘用户难以判断当前焦点。
建议：对齐 Input 聚焦态规范，增加主色描边或阴影。
轻微

#12 搜索无建议提示，直接过滤为空

▼
表现输入"云"后直接显示"暂无可用会议室"，无搜索建议或匹配提示，用户不知道是没有匹配项还是搜索未加载。
建议：增加搜索建议下拉，或在空结果时提示"未找到包含'云'的会议室"。
轻微

#13 区域选项多但缺少搜索能力

▼
表现区域下拉中有多个分公司/园区选项，面板一次只显示少量选项，需滚动查找。长区域名称存在截断风险。
建议：使用可搜索 Select 组件（showSearch）。
轻微

#14 "当前时间段可用/全部会议室"选中态区分度一般

▼
表现选中态主要依赖蓝色边框和文字颜色，未选中态为普通文字，对比度不强，用户需仔细看才能确认当前视图。
建议：选中项增加背景填充，与未选中项形成更明显的视觉差异。
轻微

#15 快速操作时下拉面板残留打开

▼
表现连续点击不同筛选控件后，前一个下拉面板可能仍停留在界面上，遮挡部分卡片区域。
建议：切换其他筛选条件时自动关闭已打开的 Select 面板。
轻微

#16 AI推荐标签尺寸偏小，未对齐标准 Tag 组件

▼
表现"AI推荐"标签高度较小，更像自定义徽标而非标准 Tag 组件。与规范中 Tag 的固定高度、圆角、padding、字号不一致。
建议：对照 Tag 组件规范统一高度、字号、圆角、padding、图标间距。
轻微

#17 滚动条样式较轻，加载更多反馈不明显

▼
表现滚动后加载了更多会议室，但滚动条视觉存在感弱，用户可能误以为没有滚动成功。
建议：增加 loading 状态动画，加载完成后保持自然滚动位置。
轻微

#18 新建会议底部操作区与内容区分隔不清晰

▼
表现"取消/保存"按钮贴近窗口底部，下方表单内容只露出一部分，用户可能忽略仍有可滚动内容。
建议：底部操作区固定（sticky），内容区独立可滚动，两者有清晰分隔线。

对照 Lingee UI 设计规范的核心偏差

Spacing（间距）— 基于 4px 网格

1卡片整体间距基本符合 4px 网格，但卡片内部留白偏多，信息密度偏低，建议调整卡片高度或增加有效信息。

Button（按钮）— md 规格 28px

2"立即预订"按钮视觉高度约22-24px，疑似未达到 md 规格的 28px，需确认实际 CSS 尺寸。

Dialog（弹窗）— 推荐宽度 460/640/720px

3预订流程使用了约1080px的独立大窗口，严重偏离规范推荐的弹窗尺寸。建议改为 Modal 或在规范中声明例外。

Input（输入框）— 聚焦态主色描边

4搜索框聚焦时缺少明显的主色描边或阴影，不符合 Input 聚焦态规范。

Tag（标签）— sm/md/lg 三种尺寸

5"AI推荐"标签未对齐标准 Tag 组件的任一尺寸规格，高度偏小，与整体标签体系一致性弱。
