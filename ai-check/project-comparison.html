02 / 定位

解决不同的问题

Design Review（2025.04）是一个设计还原度检查工具 — 给它两张图，它告诉你“差在哪、差多少”。

AICheck（2026.08）是一个 AI 驱动的全流程走查方案 — 它代替测试工程师完成从打开应用到输出报告的整个过程。

03 / 技术栈

底层技术差异

维度Design Review 旧AICheck 新
语言TypeScript 完整工程（src/dist/web）JS 脚本 + HTML 报告

工程化完整 npm 包，有 CLI + Web + Claude Code Skill脚本集合 + Skill（Qoder / Claude Code）
04 / 工作流

从输入到输出的全过程

步骤Design ReviewAICheck
1. 输入人工提供 2 张截图或 URL配置文件 + 一句话触发
2. 截图Puppeteer 自动截（仅网页）Computer Use / Playwright 自动截图
3. 对比像素算法量化差异 + 可选 AIAI 看截图判断问题
4. 代码不涉及解包 asar → 扫描硬编码

05 / 各自优势

Design Review 更强的地方

✓ 量化精度

  • pixelmatch 精确计算差异像素数
  • CIE76 DeltaE 感知色差，比人眼更客观
  • 输出“差异 3.7%”这种精确数值

✓ 易用性

  • 在线工具，拖两张图就出报告
  • 任何人打开链接就能用
  • 不需要 IDE、不需要配置

✓ 工程完整度

  • Claude Code Skill、在线工具、本地 CLI 三种用法
  • npm install 即可使用
  • 支持多种 AI 后端切换

× 局限

  • 只支持网页（Puppeteer 不能操作桌面）
  • 不涉及代码层面检查
  • 需要人工提供截图

AICheck 更强的地方

✓ 全自动化

  • 打开应用 → 操作 → 截图 → 扫描 → 对比 → 出报告
  • 配置驱动，一句话触发
  • 支持任何桌面应用（不限于网页）

✓ 代码层面

  • 解包 asar 扫描硬编码
  • 精确到文件、具体值
  • 有源码时可直接定位行号

✓ 报告可用性

  • Tab 式布局，按类别查看
  • 数据卡片点击跳转详情
  • 文件级定位，开发可直接改

× 局限

  • AI 视觉判断偏主观，无法量化“差多少”
  • 需要在 IDE 里使用，门槛较高
  • 无在线工具，不便分享给非技术人员
06 / 结论

互补，不替代

最佳方案 = AICheck 的全自动流程 + Design Review 的量化引擎

如果将两者合并：用 Computer Use 自动操作应用截图，用 pixelmatch + CIE76 量化 Figma 差异，用 token-scan 扫描代码硬编码，再套上 Design Review 的在线工具形态 — 那就是一个既有 AI 判断“有什么问题”、又有算法量化“差了多少像素”的完整走查平台。
