用 AI 做 UI 走查是什么体验

Hoho · 2026-08-04 · 阅读约 5 分钟
01 / 起因

传统走查，太费人了

做过设计走查的人都知道，这是一个高度重复且主观的工作。你需要手动打开每一个页面，逐像素对比设计稿，手动截图、标注、记录问题，再整理成文档发给开发。

一轮完整走查下来，动辄 30-50 个问题，光是截图+标注就要花半天。而且走查质量高度依赖个人经验和当时的注意力 — 你今天状态好就多发现几个，状态差就漏掉几个。

那能不能让 AI 来做这件事？不是让它直接“看”一张图说好不好，而是像真人一样 — 打开应用、操作界面、截取不同状态、对照设计规范、输出结构化报告。

于是我做了一个实验：让 AI Agent 完整走查金蝶灵基的会议室预订和对话功能，看看它能发现什么。

02 / 技术手段

三个能力支柱

这次走查不是让 AI “看一眼截图打分”，而是让 AI Agent 像真人测试员一样操作桌面应用。它背后依赖三个关键技术：

🖥️

Computer Use

AI 直接操控桌面：拖拽窗口测试响应式、点击按钮、在输入框打字、截图取证。相当于一个能看屏幕的远程测试员。

🌐

Browser Agent

用浏览器代理访问设计规范站（SPA 应用），提取间距、字号、按钮高度等具体数值，作为走查的评判基准。

📋

对照评审

Heuristic Evaluation — 将截图中的实际表现与规范数值逐项比对，自动归纳严重/中等/轻微问题并生成报告。

03 / 走查流程

从打开应用到输出报告

整个过程不需要写任何测试脚本，也不需要设计稿。AI 就像一个刚入职的测试同学，但它的操作速度比人快 3-5 倍，而且不会遗漏检查项。

打开应用 & 截取基准

AI 操控桌面打开灵基应用，截取默认窗口状态作为基准截图。

窗口缩放极限测试

拖拽窗口到最小尺寸（测试响应式）、窄宽度、全屏最大化，每个状态截图记录布局问题。

交互操作测试

点击筛选器、下拉框、搜索、按钮，快速连续操作，测试加载态、面板残留、焦点状态等交互细节。

规范对照

Browser Agent 访问 Lingee UI 规范站，提取 Button md=28px、Dialog=460/640/720px、Spacing 4px 网格等数值。

输出 HTML 报告

将所有发现按严重/中等/轻微分级，嵌入截图，生成可交互的 HTML 走查报告。

05 / 思考

AI 走查的边界在哪里

实验下来，有几个比较明确的结论：

✓

响应式 & 布局问题发现率很高。AI 可以系统地测试多种窗口尺寸，不遗漏截断、溢出、列数不降等问题。这类问题人工走查经常漏。

✓

规范偏差检查很稳定。只要规范数值明确（如按钮高度 28px），AI 就能准确判断实际实现是否偏离，不受主观影响。

▵

视觉美感判断还做不了。颜色搭配是否和谐、留白是否舒适、视觉层次是否清晰 — 这些需要设计直觉的问题，AI 目前只能给出“符合/不符合规范”的二元判断。

▵

交互逻辑深度不足。对于需要多步骤、多状态联动的复杂业务逻辑（如审批流程），AI 只能测试表层 UI，无法理解业务流程是否正确。

✓

未来方向：AI 走查 + 人工审核。AI 负责批量扫描布局和规范性问题，人工聚焦在设计意图和业务逻辑的验证上，效率可以提升 3-5 倍。
